遊戲頻道測量方式

  • 量測主機：ISP 為中華電信，物理位置在新竹；不登入遊戲，結果只代表這條線路。
  • 對象：娜歐、貝婷、愛麗沙三個伺服器，每個伺服器上的 CH1–CH13 與 HOUSE，共 42 個頻道，每個頻道各保持一條連線。
  • 方式：對每個頻道建立 TCP 連線，每 0.5 秒送一個小封包，伺服器會原樣回傳，量來回時間（RTT）作為數據。每條連線用滿 5 分鐘就重新連線，換一條網路路徑；每條連線的第一筆不計（剛連上時偏高）。沒有回應的算逾時，不計入延遲。
  • p50、p95、p99：分別代表 50%／95%／99% 的 PING 低於這個值，由上方所選時間範圍內所有 RTT 合計的統計；近一天的數值由直方圖推估，誤差約 2%。
  • 最小：上方所選時間範圍內最快的一次 RTT，代表這條線路本身的延遲下限。42 個頻道的伺服器在同一個地點，最小值通常相差不到 1 ms；若所有頻道的最小值一起升高，代表網路換了路徑。
  • 爆PING：延遲 ≥ 100 ms，會卡 0.1–0.3 秒；遊戲走 TCP，一個封包慢了後面都得等，所以跟體感卡頓最相關。爆PING 率是每 1000 次 PING 中的次數（‰）。

對照組測量方式

  • 對象（由近到遠）：
    • local節點1　192.168.0.1（家裡路由器）
    • HiNet節點1　168.95.98.254（中華電信第一站）
    • HiNet節點2　210.242.214.241（中華電信網路的出口，之後接到是方電訊）
    • 是方節點　150.116.62.94（是方電訊，接到遊戲橘子之前）
    • 遊戲橘子入口1–4　210.208.88.73、210.208.88.77、112.121.93.113、112.121.93.117（遊戲橘子網路的入口，四台分流，每條連線只會經過其中一台）
    • 遊戲橘子節點　210.208.87.70（遊戲伺服器的前一站）
    • HiNet DNS　168.95.1.1
    • Cloudflare DNS　1.1.1.1
  • 方式：每 0.5 秒量一次，2 秒沒回應算逾時；和頻道同時量。對照組小卡的 IP 旁標有量法：
    • ICMP：local節點1、HiNet節點1 用 ping，掉包時記為逾時。
    • TCP(TTL)：HiNet節點2 之後的路由器不回 ping、也不開任何 TCP 埠。改成往遊戲伺服器送連線請求，並讓它剛好在那台路由器上過期，量路由器回報「逾時」的時間；封包不會送到遊戲伺服器，走的是和遊戲連線相同的路線。每 1 分鐘換一條線路；遊戲橘子入口四台各自找一條會經過自己的線路。
    • TCP(DNS)：HiNet DNS 與 Cloudflare DNS 維持一條 TCP 連線、送 DNS 查詢，每 1 分鐘換一條線路，和頻道一樣掉包會由重傳補回、變成爆PING。
  • 爆PING、p50、p95、p99、最小的算法和頻道相同。
  • 路由器用 CPU 回應 ping 與逾時回報、DNS 伺服器要處理查詢，所以通常比實際線路慢一點、也比較抖；「最小」最接近線路本身的延遲。
  • 對照組不列入伺服器總覽、熱度圖與表格。
